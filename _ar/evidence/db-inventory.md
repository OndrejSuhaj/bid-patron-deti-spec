## 5. Config-based data model (thin, CMS-oriented)

The custom **entities** carry the bulk of the domain fields as code-defined base fields; the Drupal config data model is comparatively thin. Evidence: [config/](../../intake/current-solution/_source/patronus/config/).

- **Node content types (5):** `blog`, `form_page`, `page` (RO "Pagină simplă"), `page_cz`, `success_page`.
- **Field storages:** 29 `field.storage.*.yml`; **Field instances:** 37 `field.field.*.yml`. Instances are CMS-oriented: node.blog (6), node.page (4), node.page_cz (3), node.success_page (2), node.form_page (2); user.user (3: user_bank_account, user_image, user_name); taxonomy_term bundles (voucher_types 3, blog_category 3, partners 2, category 2); block_content.reusable_block (3); media (2); **campaign.campaign (1: `metatags`)**; **application.application (1: `status_note`)**. All other custom-entity fields are code-defined base fields.
- **Vocabularies (10):** `blog_category`, `category` (Oblast pomoci), `city` (Město), `faq_categories`, `gift_confirmation`, `housing_type`, `income_type`, `partners`, `pattern_categories`, `voucher_types`.

## 6. Open questions / missing evidence

- **Production DSN / credentials / DB topology — `Blocked — scrubbed`.** No `settings.php`/`.env`/`sites/*` in the intake; only a dev `docker-compose.yml`. Engine = MariaDB is derived, not read from a live connection. Never echo credential values (none captured).
- **Physical column DDL for entity tables — mostly inferred.** With no `hook_schema()` for ~35 entities, exact column types, NOT NULL, generated indexes, and unique keys are Drupal-framework-generated and **not verified against a live/last-installed schema** (static pass, no running instance — see [../tasks/Runtime-truth-policy.md](../tasks/Runtime-truth-policy.md)).
- **`field.field.*` instance semantics — `Indexed only`.** 37 instances counted and located by bundle; individual field-config semantics not fully expanded.
- **Config-vs-annotation translation conflicts.** Several entities (`campaign`, `application_action`, `email`, `feedback`, `costs_entity`, `snapshot_entity`, `contract`, geo entities) have `language.content_settings.*` config and/or per-field `setTranslatable(TRUE)` while the `@ContentEntityType` annotation declares no `data_table`/`translatable`. Recorded as `Conflict — requires clarification`, not resolved. Per-entity detail in db-models.md.
- **Dangling entity_keys / commented-out fields.** Several entities declare a `label`/`status` entity_key pointing at a field that is not defined, or expose a getter for a commented-out field (`application_log` label→`name`; `campaign_log` label/status; `email` `body2`; `application_reaction` `action`; `scoring_entity` label→`name`; `blacklist`/`contract_template` status). Recorded per entity as `Conflict / Uncertain`.
- **`maib_example` runtime use — `Hypothesis: unused scaffolding`.** Not evidenced as used.
- **Custom field-type storage internals (`rc`, `eligible_email`, `country_phone`, `worker_entity_reference`, `campaign_entity_reference`).** Field-type plugin `schema()` was read for `worker_entity_reference` (adds `is_admin`) but the organisation verdict could NOT re-confirm it within its allowed scope (`constraints_confirmed=false`); others not fully expanded.
