**Reading notes (apply to every entity):**
- `source_of_truth` is each entity's `baseFieldDefinitions()` + `@ContentEntityType` annotation unless noted `mixed` (extra config field / raw-SQL side table). **No `hook_schema()` exists for these entities** (except where stated) — physical DDL is Drupal-generated, not source-declared.
- Every content entity implicitly gets `id` (serial PK), `uuid` (unique key), `langcode`; revisionable entities add `vid` + `revision_user`/`revision_created`/`revision_log`. These implicit keys are **framework conventions**, not declared constraints, and are omitted from field tables unless load-bearing.
- `entity_reference` fields are **Drupal soft references** (target_id column); Drupal does **not** create DB-level FKs. `req.` = field-level `setRequired()` (validation/form-level, not a guaranteed DB NOT NULL). `card.` = cardinality (1 or ∞ = `CARDINALITY_UNLIMITED`).
- Many entities call `setRevisionable(TRUE)`/`setTranslatable(TRUE)` on individual fields while the entity type declares no revision/data table — those flags are **inert**. Noted once per entity, not per field.
- **Verification:** where an adversarial `verdicts` entry exists, a **Verification:** line states its confidence and applies corrections. 8 entities were verified (application, campaign, contact, contract, organisation, transaction, transaction_recurring, voucher).
