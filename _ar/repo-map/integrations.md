## 2. Email / transactional messaging

- **Domain validation** — [email/src/EmailService.php](intake/current-solution/_source/patronus/web/modules/custom/email/src/EmailService.php) calls `https://domain-availability.whoisxmlapi.com/api/v1` (WhoisXMLAPI) via `\Drupal::httpClient()`. `Confirmed` (per integrations scan).
- **Mail plumbing** — `drupal/mailsystem ^4.3` mail-plugin architecture; dev SMTP via MailHog (`mailhog:25`). `Evidence:` [composer.json](intake/current-solution/_source/patronus/composer.json), [docker-compose.yml](intake/current-solution/_source/patronus/docker-compose.yml).
- **Transactional dispatch** — [patron_base MailingQueue](intake/current-solution/_source/patronus/web/modules/custom/patron_base/src/Plugin/QueueWorker/) + `patron_base.smartmailing` service; [notification](intake/current-solution/_source/patronus/web/modules/custom/notification/) sends on application-status-change events. `Evidence:` patron_base services + notification EventSubscriber.

> Notification content (status → role → text → channel) is **not** modeled here — that is the Notification Matrix in [intake/test-scenarios/](intake/test-scenarios/) and the MSG layer (later AR passes).

## 3. Marketing / CRM / analytics

- **Mautic** (marketing automation) — [patron_base/src/Plugin/QueueWorker/MauticQueue.php](intake/current-solution/_source/patronus/web/modules/custom/patron_base/src/Plugin/QueueWorker/MauticQueue.php) (`id = mautic_queue`) uses `Mautic\MauticApi` + `Mautic\Auth\ApiAuth`, base URI `https://m.patrondeti.cz/api`, BasicAuth from env `MAUTIC_USER`/`MAUTIC_PASS` (redacted). Also [mautic](intake/current-solution/_source/patronus/web/modules/custom/mautic/) module + `mautic/api-library` composer dep. `Confirmed`.
- **Facebook Conversions API (CAPI)** — [facebook_leads/src/Plugin/rest/resource/FacebookResource.php](intake/current-solution/_source/patronus/web/modules/custom/facebook_leads/src/Plugin/rest/resource/FacebookResource.php): a Drupal `@RestResource` at `/api/3.2/facebook` that **forwards** pixel events (`Lead`/`Purchase`/`CompleteRegistration`), SHA-256-hashes user data and POSTs to `https://graph.facebook.com/v16.0/{pixel_id}/events`. `Partial` — see correction below.
- **Google Tag Manager / GA** — `drupal/google_tag ^2.0` + `config/google_tag.settings.yml`. `Confirmed` (config present).
- **Facebook Pixel** (client-side) — `drupal/facebook_pixel ^2.0`. `Confirmed` (composer).

> ⚠ **Correction (verify pass):** `facebook_leads` is **not** an inbound Facebook *Lead Ads webhook* as first scouted — it is an **outbound Conversions API forwarder** (the `post()` handler is a no-op; ingestion is via `get()` query params). A hardcoded pixel id + access token exist in `sendData()` (token redacted).

## 4. External storage / files / index

- **OneDrive / Microsoft Graph** — [onedrive/src/Command/OnedriveCommand.php](intake/current-solution/_source/patronus/web/modules/custom/onedrive/src/Command/OnedriveCommand.php) (`onedrive:import:invoices`): imports invoice PDFs from a OneDrive/SharePoint drive and attaches them to campaign applications (`private://attachments_audit`). Token from `https://login.microsoftonline.com/{tenant}/oauth2/token`. `microsoft/microsoft-graph ^1.70` (composer). `Partial` — see correction.
- **Elasticsearch (audit log)** — [elasticsearch/src/Elasticsearch.php](intake/current-solution/_source/patronus/web/modules/custom/elasticsearch/src/Elasticsearch.php): hardcoded `http://elasticsearch:9200`; **writes request/response audit records** (ip, user-agent, method, query, request, response, status, referer, timing). It does **not** query/search. `Confirmed` (as an audit-log store).
- **Elasticsearch (search index)** — [patron_search](intake/current-solution/_source/patronus/web/modules/custom/patron_search/) (`EsUploadCommand`, `EsUploadQueue`) bulk-indexes for full-text search. `Partial` (from scan; endpoint not re-verified in this pass).
- **PDF generation** — `mpdf/mpdf ^8.1` + `mpdf/qrcode ^1.1`. `Confirmed` (composer). Consumers (invoices/vouchers/contracts) not re-verified — `Hypothesis` on exact use-sites.
- **Image handling** — [simple_image_rotate](intake/current-solution/_source/patronus/web/modules/custom/simple_image_rotate/); Drupal image styles (~62 config).

> ⚠ **Correction (verify pass):** the OneDrive OAuth2 grant is **`grant_type=password` (Resource Owner Password Credentials / ROPC)** with a hardcoded username/password — **not** client-credentials, despite a client_id/client_secret being sent. See §11 security note.

## 5. Notifications / ops alerting

- **Slack** — [slack_integration](intake/current-solution/_source/patronus/web/modules/custom/slack_integration/) registers a `logger.slack` channel: posts `ERROR` → `webhook_url_errors`, `CRITICAL` → `webhook_url_checks` via `httpClient->post(...)`. Webhook URLs from `Settings::get('slack')` (not hardcoded). `Confirmed` — it is **error/health alerting**, not user messaging.
- **Telegram** — [telegram_integration](intake/current-solution/_source/patronus/web/modules/custom/telegram_integration/) registers a `logger.telegram` channel: forwards error-severity logs to `https://api.telegram.org/bot{botId}/sendMessage`; bot token/chat id from `Settings::get('telegram')` (redacted). `Confirmed` — error alerting (class docblock is mislabeled `SlackLogger`, likely copy-paste).
- **Firebase** — `kreait/firebase-php` is a composer dep and a command [campaign/src/Command/CampaignFirebaseSyncCommand.php](intake/current-solution/_source/patronus/web/modules/custom/campaign/src/Command/CampaignFirebaseSyncCommand.php) (`campaign:firebase:sync`) exists — **but** that command only re-saves `CampaignEntity` records and prints *"Please run Jenkins / Files Synchronization"*; it contains **no** Firebase SDK usage. `Uncertain — the Firebase library's actual call-site is not evidenced; verify in entity save/hook code before asserting.`
- **SMS** — No dedicated SMS gateway found in custom code; only MobilPay's SMS-payment request type inside Netopia. `Uncertain / likely none`.

## 11. Security-relevant observations (redacted)

Surfaced during verification — recorded as **current-state facts for the rebuild**, not reproduced secrets:

- **Hardcoded credentials in source** — [onedrive/src/Command/OnedriveCommand.php](intake/current-solution/_source/patronus/web/modules/custom/onedrive/src/Command/OnedriveCommand.php) contains cleartext tenant id, client id, client secret, and a username/password (ROPC). `Evidence:` the two files above (verify pass). Flagged for the target-state hardening backlog; **not** a current-behavior defect claim.
