## Master scheduler (ground truth)

All Drupal `hook_cron` jobs are driven by a single OS-cron entry running the platform cron **hourly**:
`CRONTAB: "0 * * * * drush -r /var/www/html/web cron"` (dedicated `crond` container —
`intake/current-solution/_source/patronus/docker-compose.yml:70`). Cron threshold config:
`config/system.cron.yml` (warning 172800s / error 1209600s; `logging: true`).

Because the tick is hourly, individual scheduler jobs that must run daily **self-throttle** via a
persisted `\Drupal::state()` key (seeded to a fixed hour, then a `+1 day <= now` gate). Jobs without a
throttle run on **every** tick. Async-consumer queues have **no cron key** and no active module cron
drain — they are drained only by explicit CLI (JOB0022 / JOB0012).

## Legend

- **Type** — scheduler / poller / async-consumer / repair / batch (per rules-JOB.md).
- **Trigger (verified)** — the actual source mechanism (cron hook / queue / CLI) and cadence where
  evidenced. "hourly tick" = the platform cron container; "self-throttle" = a `\Drupal::state()`
  daily gate inside the job.
- **Confidence** — AR evidence vocabulary (Confirmed / Partial / Dormant / Hypothesis-on-scheduling).
- **Region** — CZ / RO / MD gating as coded (Settings country/environment guards); "all" = no
  in-code region gate.
