## 4. Observed trigger patterns
- **Shared callback path collision:** ComGate *and* MAIB both bind `/transaction/status_update` (FL021/FL022) — routing disambiguation is a mining question (`Missing evidence: how the two controllers coexist on one path`).
- **Two event buses:** `ApplicationStatusUpdateEvent` (FL005) and `TransactionUpdateEvent` (FL028) — status changes and payment-PAID are the two main internal fan-out points.
- **Cron-gated integrations:** most external pulls (Moneta, IMAP, ComGate/Netopia recurring) run once/day, environment-gated (CZ/RO/production) — Multi-tenant + Async everywhere.
- **REST API surface is large:** account (~13 resources, versioned v31/v32), transaction, voucher, contact, patron_base — headless/mobile client. `/api/init` (FL018) likely bootstraps the SPA.
- **Synchronous "queues":** `mailing_queue` exists but `USE_QUEUE=FALSE` → mail sent inline (no retry) — an async boundary that is not actually async.
- **Admin-heavy:** the bulk of 156 routes are `/admin/*` back-office CRUD/reporting (ŽÁDOST BACK, FINANCE, RISK).
