## Legend (notation)

| Notation | Meaning |
|---|---|
| `A --sync--> B` | **Synchronous** in-request call: A calls B and waits (same request thread / transaction) |
| `A ~~event~~> B` | **Event-like** transition: A raises a domain event / entity-save side-effect that B reacts to (**synchronous in-request today** unless marked `[async]`) |
| `A ==queue==> B` | **Async queue** boundary: A enqueues; a worker/cron drains to B out-of-band (genuinely eventual) |
| `A ..cron/CLI..> B` | Scheduled or CLI-triggered pull/push (background, not request-driven) |
| `A ..external..> X` | Call **out** to an external system X (adapter boundary) |
| `X ~~webhook~~> A` | External system X calls **in** (callback / IPN / webhook) |
| `⟂ DORMANT` | Path exists in code but is inert in the current state (`[recommendation]` to drop/rebuild) |
| `⚠ looks-async / is-sync` | A boundary a rewrite treats as async but which is **synchronous in-request today** |

## Reader's summary — what actually crosses a real boundary today

- **Only three paths are genuinely async/decoupled:** search indexing (`==search-index queue==>`; the flow is now
  mined — FLW0032, Confirmed, residual Partial on drain scheduling only), the Mautic contact-upsert queue, and the cron/CLI processors (recurring, reconciliation,
  CSV export, OneDrive import, scheduled publish, daily org index).
- **Everything else that "looks like" an event is synchronous in-request** — the status orchestration seam
  (HS01), the Transaction money hub (HS03), the Application↔Campaign lock-step (INV04, alert-only), the
  Contract→Application signature coupling (INV11), the scoring→Contact classification (INV15/HS08), and even the
  "queued" transactional mail (queue disabled — HS13). These are the boundaries a rewrite must make real (see
  CONSISTENCY-boundaries §4).
- **External boundaries** are the 17 systems in ARCH0001 §5; the highest-risk are the un-authenticated payment
  callbacks (HS12), the fragile reconciliation legs (HS05), and the fail-open Nager.Date working-day check.
- **One dormant path** (recommendation) is present but inert — a drop-or-rebuild decision, not current behaviour.
