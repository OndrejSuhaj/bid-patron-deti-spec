## 0. Classification model

Per the agent spec, each entity is assigned one **primary class**:

| Class | Meaning (as applied here) |
|---|---|
| **Domain** | Owns transactional/domain state and lifecycle; a rewrite must reproduce its behaviour. |
| **Configuration** | Behaviour/reference config or curated presets; drives the system but has no per-instance domain lifecycle. Includes pure reference/lookup data. |
| **Join / Assignment** | Exists to associate two other entities; little own state. |
| **Projection / Reporting** | Read-model / reporting datum; derived or entered-for-reports, consumed read-only. |
| **Audit / Log** | Append-only trail of something that happened; created-never-mutated. |
| **Infrastructure / Technical** | Framework/platform/plumbing table; not domain-meaningful. |
| **Uncertain** | Cannot be confidently classified from current evidence. |

Two entities are also tagged **Content** as a domain sub-note (Partner, Blog) — they are content-management
records with no domain behaviour; they sit under **Domain** for the primary axis only because they are
custom application entities, but the aggregate model treats them as Content ([DOMAIN-aggregates §3](DOMAIN-aggregates.md)).

**Platform Suspicion** flag (per spec failure-mode policy): raised where an entity looks like shared/
framework/vendor plumbing rather than Patronus domain. Raised for: `maib_example`, `login_history`,
`email_domain`, and the Drupal-core entities (media, block_content, node bundles).

## 7. Uncertain (0 unresolved)

No entity is left wholly unclassifiable. All ambiguities are **local** (dangling entity_keys, annotation-vs-
config translation, dormant/no-writer) and are recorded against an otherwise-confident primary class rather
than forcing an `Uncertain` bucket. The items carrying the most residual ambiguity (surfaced for manual
review, but **classified**):

|---|---|---|---|
