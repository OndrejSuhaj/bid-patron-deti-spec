## 0. Landscape total & how it was counted

The task brief referenced "~105 entity classes". That figure is the number of **`.php` files** under
`web/modules/custom/*/src/Entity/`. Those 105 files decompose as (verified):

| File role under `src/Entity/` | Count | Note |
|---|---|---|
| `@ContentEntityType` class | **36** | actual persisted content-entity types |
| `@ConfigEntityType` class | **1** | `application_statuses` (config entity, no base_table) |
| `*ViewsData` helper class | 35 | Drupal Views integration, **not** an entity type |
| `*Interface` | 33 | entity interfaces, **not** an entity type |
| **Total `.php` files** | **105** | |

`Evidence:` file-role scan over `web/modules/custom/*/src/Entity/*.php` (36 `@ContentEntityType`,
1 `@ConfigEntityType`, 35 `ViewsData`, 33 interfaces).

**⇒ The true persisted-entity landscape is 37 custom entity types (36 content + 1 config)**, matching
[db-inventory.md §2](../evidence/db-inventory.md) exactly — **not** 105. In addition there are **4
non-entity persisted tables** (2 `hook_schema` + 2 raw-SQL/update-hook), and a set of **Drupal-core
entities** that carry config fields but are not custom types. All are inventoried below.

| Landscape segment | Count | Section |
|---|---|---|

| Custom config entity type (`@ConfigEntityType`) | 1 | §1 (row `application_statuses`) |

## 5. Cross-entity relationship signals (soft references only)

**No DB-level foreign keys exist** — every cross-entity link is a Drupal soft `entity_reference`
(target_id) or a plain string/int (logical link). Referential integrity is application-enforced.
`Evidence:` [data-model-signals §5](../repo-map/data-model-signals.md); [db-models.md](../evidence/db-models.md) per-entity Relations lines.

Highest-fan-in / structurally central entities (most-referenced):
- **user** — referenced by nearly every entity (`user_id` owner/author).
- **application** — referenced by aprofile, application_log, application_session (string), blacklist, email, application_states.
- **campaign** — referenced by transaction, voucher, donation_confirmation, feedback, email, blog(cta).
- **contact** — referenced by application (child/lead), aprofile (fundraiser/child/patron/school/employer), organisation, supplier(city→taxonomy).
- **transaction** — referenced by transaction_recurring, voucher; self-ref parent.

Self-referencing entities: `campaign` (parent), `transaction` (parent), `contact`/`contract`/`user_note`/`application`/`application_reaction`/`contract_template` (revision self-links).
